# Tradfri Zigbee 抓包器（sniffer-tradfri）使用说明

基于 Silicon Labs **EFR32MG1P132F256IM32**（Cortex-M4）的 IEEE 802.15.4 / Zigbee
抓包固件。它把收到的空口报文封装成 **IEEE 802.15.4 TAP** 帧，通过串口以十六进制
行输出，再由 `zbsniff` 转成 pcap 供 Wireshark 解析。

- 默认链路类型：`LINKTYPE_IEEE802_15_4_TAP`（283），携带**频道 / RSSI / LQI** 元数据。
- 支持在 Zigbee 信道 11–26 之间切换，默认信道 15。
- 支持按键切换、串口命令切换两种方式。

---

## 1. 硬件连接

| 信号 | 引脚 | 方向 | 说明 |
|------|------|------|------|
| 按键 | **PA0** | 输入 | 上拉至 VCC，按下为低电平（下降沿触发） |
| LED  | **PB13** | 输出 | 高电平点亮 |
| UART0 RX | **PB14** | 输入 | 路由位置 `RXLOC_LOC8` |
| UART0 TX | **PB15** | 输出 | 路由位置 `TXLOC_LOC10` |

串口参数：**115200 baud，8 数据位，无校验，1 停止位（8N1）**。

> 引脚定义见 `config.h`，按键初始化在 `main.c`（`gpioPortA, pin 0`，
> `gpioModeInputPullFilter` + 下降沿外部中断）。

---

## 2. 功能特性

1. **信道切换（按键）**：按下 PA0 按键，在信道 11→12→…→26→11 之间顺序循环切换，
   每次切换 LED 闪 2 次，并在串口回显 `CH N`。
2. **信道切换（串口）**：通过串口命令切换、查询、绝对跳转信道（见第 6 节）。
3. **报文输出**：每个收到的 802.15.4 报文，先输出 36 字节 TAP 伪头（含频道、
   RSSI、LQI、FCS 类型），再输出 PSDU 十六进制，末尾换行。
4. **接收指示**：每收到一个报文，LED 闪 1 次。

LED 闪烁语义（闪烁半周期 30 ms，一个完整亮灭约 60 ms）：

| 闪烁次数 | 含义 |
|---------|------|
| 2 次 | 刚刚切换了信道 |
| 1 次 | 刚收到一个报文 |


## 6. 串口控制

用任意串口终端（`screen` / `minicom` / `picocom` / pyserial 等）以 **115200 8N1**
连接设备。设备节点示例：`/dev/tty.usbmodem0000001901731`（macOS）。

```bash
# macOS 查看当前串口设备
ls /dev/tty.*
```

### 命令一览

| 输入 | 功能 | 回显 |
|------|------|------|
| `+` 或 `n` / `N` | 下一个信道（11→…→26 循环） | `CH N` |
| `-` 或 `p` / `P` | 上一个信道（26→…→11 循环） | `CH N` |
| `<数字>` + 回车 | 跳转到绝对信道（11–26），如 `15`⏎ | `CH 15` |
| `?` | 查询当前信道 | `CH N` |

- 信道超出 11–26 时回显 `ERR`（不会切换）。
- 输入数字会累积，回车（`\r` 或 `\n`）提交；非数字/非法字符会清空输入缓存。

### 验证示例（pyserial）

```python
import serial, time
s = serial.Serial("/dev/tty.usbmodem0000001901731", 115200, timeout=1)

def send(cmd):
    s.write(cmd)
    time.sleep(0.2)
    print(cmd, "->", s.read(s.in_waiting).decode(errors="replace").strip())

send(b"?")      # CH 15
send(b"+")      # CH 16
send(b"-")      # CH 15
send(b"26\r")   # CH 26
send(b"?")      # CH 26
```

## 7. 抓包与 Wireshark（zbsniff）

`zbsniff` 是一个 Python 脚本：它打开串口，把每行十六进制报文包成 pcap 记录，
pcap 头里声明链路类型 283（`LINKTYPE_IEEE802_15_4_TAP`）。它会丢弃长度 < 36 或
版本字节非 0 的行，从而过滤掉固件的调试/回显文本（如 `CH N`、`test`）。

### 配置串口设备

`zbsniff` 第 23 行的 `device` 必须与实际设备一致：

```python
device = "/dev/tty.usbmodem0000001901731"   # 改成 ls /dev/tty.* 看到的实际节点
```

> 注意：当前文件里是 `/dev/tty.wchusbserial1430`，该设备并不存在，需要改成
> 实际节点（例如上面的 `usbmodem`）后才能抓包。

### 实时抓包并导入 Wireshark

```bash
cd /Users/mybays/develop/efr32/efr32_proj/sniffer-tradfri
python3 zbsniff | wireshark -k -i -
```

### 保存为 pcap 文件（之后用 Wireshark 打开）

```bash
python3 zbsniff > capture.pcap
wireshark capture.pcap
```

在 Wireshark 中，包会显示为 IEEE 802.15.4 TAP 类型，可从链路元数据中看到
**Channel / RSSI / LQI**。

## 8. IEEE 802.15.4 TAP 报文格式（参考）

固件输出的每一行 = 36 字节 TAP 伪头 + PSDU，整体十六进制，末尾 `\r\n`。
TAP 头为小端序：

| 偏移 | 字段 | 字节数 | 值 / 说明 |
|------|------|--------|-----------|
| 0 | version | 1 | `00` |
| 1 | reserved | 1 | `00` |
| 2 | length | 2 | `24 00`（=36，头长度，小端） |
| 4 | TLV 类型 0（FCS Type） | 2 | `00 00` |
| 6 | TLV 长度 | 2 | `01 00`（值 1 字节） |
| 8 | FCS 类型值 | 1 | `00`（无 FCS） |
| 9 | 对齐填充 | 3 | `00 00 00` |
| 12 | TLV 类型 1（RSS） | 2 | `01 00` |
| 14 | TLV 长度 | 2 | `04 00`（值 4 字节） |
| 16 | RSSI | 4 | IEEE-754 单精度 float，单位 dBm，小端 |
| 20 | TLV 类型 3（Channel） | 2 | `03 00` |
| 22 | TLV 长度 | 2 | `03 00`（值 3 字节） |
| 24 | 信道号 | 2 | 小端，如 `0f 00` = 信道 15 |
| 26 | 信道 page | 1 | `00` |
| 27 | 对齐填充 | 1 | `00` |
| 28 | TLV 类型 10（LQI） | 2 | `0a 00` |
| 30 | TLV 长度 | 2 | `01 00`（值 1 字节） |
| 32 | LQI | 1 | 链路质量指示 |
| 33 | 对齐填充 | 3 | `00 00 00` |
| 36 | PSDU | 变长 | 802.15.4 帧（不含 FCS，不含 PHY 长度字节） |

示例（信道 15、RSSI = -67.0 dBm、LQI = 206，PSDU 长 0x81 字节）：

```
00002400 00000100 00000000 01000400 000086c2 03000300 0f000000 0a000100 ce000000  <psdu...>
```

- `000086c2` 是 `-67.0f` 的小端 IEEE-754 表示。
- FCS 类型为 0，表示 TAP 伪头后不包含 FCS（Wireshark 据此不复算 FCS）。

## 9. 常见问题（FAQ）

**Q1：串口没有回应任何命令？**
确认波特率 115200 8N1；确认 `uart0.c` 的 `initUart0()` 末尾执行了
`USART_IntEnable(USART0, USART_IF_RXDATAV)`（该中断曾在 `USART_InitAsync` →
`USART_Reset()` 时被清掉，导致 `RETARGET_ReadChar()` 永远返回 -1，现已修复）。

**Q2：zbsniff 没有输出任何 pcap 数据？**
检查 `zbsniff` 里 `device` 是否指向真实存在的串口（`ls /dev/tty.*`）。若设备名
不对，`serial.Serial(...)` 会直接抛异常。

**Q3：Wireshark 里包显示为乱码 / 未知类型？**
确保 pcap 链路类型为 283（`zbsniff` 头里 `283`），Wireshark 需支持
`IEEE 802.15.4 TAP`（较新版本均支持）。

**Q4：LED 不亮？**
LED 为 PB13 高电平点亮，确认硬件接法与 `config.h` 一致（`LED_PORT=gpioPortB`，
`LED_PIN=13`）。

**Q5：想抓某个固定信道？**
用串口命令 `<信道号>` + 回车（如 `20`⏎）切到目标信道，再启动 zbsniff 抓包。
